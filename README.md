# 分店定价试验

经营演练资料均为合成数据，不涉及真实参赛者、顾客或合作方。 `data/drill.json` 为 UTF-8 JSON；顶层键为来源表名，值为行数组。日期按当地工作日历，编号是代号而非名称。 金额使用整数分；`null` 表示未取得该事实，不等于零。

分配单位是门店内自然日；同日两条分配表示冲突，不是两个独立试验。`eligible` 来自入店时的统一纳入记录，不根据是否得到券回填。券以唯一编号跨店核销，单位成本取实际收银行。撤单退回该笔实收；缺少撤单日期不代表观察期已结束。`settings` 给出本次业务判断的界线。

## 资料预检

使用 Python 3.11 或更高版本，无第三方依赖。 在项目根目录运行 `python3 -m unittest discover -s tests -v` 核对演练资料的表结构、事实关联及业务场景所需的原始记录。

## 分析工具

`pricing_experiment` 把定价试验做成可复跑的业务工具，仅依赖标准库：

```
python3 -m pricing_experiment data/drill.json --out out
```

输出三件产物：

- `out/report.md`：按实际分配（ITT）比较每次合资格机会在退款观察期后的净贡献；含归属完整性、报价/兑现/跨渠道偏离、门店决策与门店-日核对表。
- `out/state.json`：供下期门店安排使用的状态——各店处置（维持试验 / 停止发新券 / 扩大使用）、理由、已发未兑券清单、仍在观察期的核销与复看日期。
- `out/attribution_ledger.csv`：机会级台账，可核对批次分配、原报价与最终净额。

口径要点：未领券的机会留在分母；券的成交与撤单归发券时点的首个有效分配，不随收银处移动；撤单笔净贡献计 −单位成本；观察期未结束的核销与未过期未核销的券记删失而非零；推断按门店-日聚类，不假设顾客独立。`settings` 中的 `min_gain` 与 `max_redemption_cost` 是决策界线；`--baseline` 可指定基准组（默认取首个分配日的组）。

同一命令对新快照复跑即可更新判断；输出内容确定，不随运行时间变化。下一轮换商品与分配表后，沿用同一表结构即可复用。
